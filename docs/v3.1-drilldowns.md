# v3.1 plan: drill-downs — yearly → categories → transactions

Status: **implemented + verified 2026-10-19** (engine + seeds + unit
tests; verified live on thor.local; see §Verification).

v3.1 is a **report-hub** release: drill-down navigation between the
finance dashboards, so a user can walk from a year to a category to a
month without typing URLs. One small engine addition (link machinery +
multi-picker nav), three seed updates (one new dashboard), no data-hub
changes, no `finance`/`hub` schema changes.

## 1. Goals

1. **Click-through navigation.** v3's `/d/yearly` and v1's
   `/d/categories` were dead ends: you could see a category's share of a
   year, but to inspect the underlying transactions you had to guess a
   URL. v3.1 makes the obvious hops clickable:
   - `/d/yearly` → `/d/categories` (category + year carried over)
   - `/d/categories` → `/d/transactions` (category + month carried over)
2. **Year-scoped categories.** `/d/categories` was trailing-12-month; it
   now takes a `year` param (calendar year) so it is a natural target for
   `/d/yearly` drill-downs and answers "where did the money go in
   category X in year Y?".
3. **Multi-picker nav.** A dashboard can now offer **several** param
   pickers (category + year; category + month), each preserving the other
   params on change/reset.

## 2. Scope

### Engine (report-hub `server/main.py` + `templates/dashboard.html`)

- **Multi-picker `param_nav`.** `layout.param_nav` may now be a **list** of
  `{param, label, all_label, query}` entries (single dict = legacy form,
  still supported). Each entry → one dropdown; the picker's onchange and
  reset preserve the *other* request params (`other_params` / `reset_qs`
  built server-side, embedded as JSON). A request value absent from the
  picker's query list is prepended (so leaf-category drill-downs show in
  the bucket-only picker).
- **Table row drill-down links.** A table card may declare
  `config.links = {<column>: <spec>}`. The href is built **server-side**
  (URL-encoded) and attached per row as `row["_links"][column]`; the
  template renders the final `href` (no client-side interpolation of row
  values). `<spec>` forms:
  - legacy string `"<target_param>"` → same dashboard,
    `?<target_param>=<row value of the linked column>` (v1 behavior, kept);
  - dict `{"dashboard": "<slug>", "params": {<target_param>: <value_spec>}}`
    — `dashboard` omitted = same dashboard.
- **Chart click links.** A chart card may declare
  `config.link = {"dashboard": "<slug>", "params": {<target_param>:
  <value_spec>}, "exclude": [<x values>]}`. The server emits a small
  `chart_link` payload (`url` / `static` / `dynamic` / `exclude`); the
  template wires an ECharts `click` handler that navigates to
  `url + '?' + qs`, substituting the clicked point's x value
  (`params.name` — pie slice name or bar x-label) for `{x}` and skipping
  excluded x values.
- **`<value_spec>`** (shared by both link forms):
  - `"{col}"` → the row's value for column `col` (tables);
  - `"{x}"` → the clicked point's x value (charts);
  - `":name"` → the card's **resolved** param value (effective value after
    validation/fallback — so the target inherits the current filter);
  - anything else → a static literal.
- **Unit tests** (`tests/test_links.py`, no DB): `_link_value`,
  `_build_link_href`, `_build_param_nav` (list/legacy/invalid/failing
  query). Run: `python3 tests/test_links.py` (or
  `docker exec report-hub python3 /app/tests/test_links.py`).

### Seeds (report-hub `seed/`)

- **`v1_finance_dashboards.sql`** — the `categories` dashboard re-scoped
  from trailing-12-month to **calendar-year**: two pickers (category +
  year), cards rewritten to `fin_cat_year_*` queries (spend + YoY vs prior
  calendar year, monthly Jan–Dec spine, top payees, transactions, all
  buckets for the year). `?category=` now accepts **bucket or leaf**
  (`allowed_query` = all category names) so `/d/yearly` leaf drill-downs
  work; defaults = top-spend bucket (Food & Dining as of 2026-10) + latest
  year (2026). Links: monthly-spend bars → `/d/transactions`
  (category = resolved picker value, month = clicked bar); all-bucket rows
  → same dashboard (`?category=<bucket>&year=<year>`).
- **`v3_yearly_review.sql`** — drill-downs added: category-mix pie slice →
  `/d/categories?category=<leaf>&year=<year>` (`Other` slice excluded);
  spend-by-year bars → switch the year picker in place; category-summary
  rows → `/d/categories?category=<leaf>&year=<year>`. The per-year
  transactions table was **removed** (replaced by the drill-down chain:
  yearly → categories → transactions). 9 cards → 8.
- **`v3_transactions.sql`** (new) — the `/d/transactions` dashboard:
  category × month. Two pickers (category + month); spend +
  vs-same-month-prior-year delta, txn count, top payees, all transactions
  (250/page). Terminal dashboard (no outbound links).

### Out of v3.1

- Deep-linking from `overview` (still a summary dashboard; its cards are
  12-month windows, not year/category scoped — a future scope change).
- Breadcrumb / back navigation (browser back works; no in-page trail).
- Auto-generated per-dataset drill-downs for hub data (v3 pattern,
  unchanged).

## 3. Design notes

- **Read-only contract preserved.** Links only build query strings over
  already-validated params and row values; the UI still performs no
  writes. Hrefs are built server-side and URL-encoded; the template never
  interpolates row values into URLs (the v1 `links` string form did
  client-side interpolation — kept for compatibility, superseded).
- **Resolved params in links.** `":name"` resolves to the card's
  *effective* param value (request value if valid, else default), not the
  raw request value — so a drill-down from a page with a fallen-back param
  carries the value the page actually rendered.
- **`{x}` is dynamic by construction.** Only the literal string `"{x}"`
  marks a dynamic value; everything else is static at render time. The
  clicked x value is substituted client-side by the ECharts handler (the
  server cannot know which point will be clicked).
- **Seeds are idempotent** (delete-then-insert per slug + explicit query
  name list) and must end with a trailing newline when wrapped in
  `START TRANSACTION; … COMMIT;` (a missing final newline glues `COMMIT;`
  onto the last comment line → silent rollback). All seed files now end
  with a newline.
- **Compose env gotcha (deployment, not code).** `docker compose up -d
  --build report-hub` interpolates `${DH_REPORTS_USER}`/`${DH_REPORTS_PASS}`
  from the *shell* environment (there is no `compose/.env`); run it with
  the homelab `.env` exported (`set -a; . /home/chuck/homelab/.env; set
  +a`) or the recreated container loses `MYSQL_USER`/`MYSQL_PASSWORD` and
  startup fails with `Access denied for user 'root'`.

  normalization, legacy + invalid + failing-query cases).

  cards, 0 card errors; pie `chart_link` =

  leaf `?category=Gas&year=2023`): 2 pickers render with `showing:` +
  reset; leaf `Gas` prepended to the bucket-only picker; monthly chart
  `chart_link` = `{url: /d/transactions, static: {category: "Food &

- `/d/transactions` (defaults + `?category=Food%20%26%20Dining&month=2024-05`
